# YBX fork inventory

Every path this fork changes relative to upstream CrossPoint, why it changes, and
how to resolve it during an upstream sync. `scripts/ybx_upstream_sync.py` parses
the table below, so keep it in sync with the actual diff.

Baselines when this inventory was written:

- Integrated upstream commit: `31dc683f` (`upstream/develop` tip, merged in `a8e0bbba`).
- Fork commits on top: `1043a2d0`, `e728f5dd`, `344185ee`, `860dd3db`.
- The original 79-path inventory has been extended for the 29 October integration.
  Counts are generated by the check below rather than kept as a stale constant.

Regenerate the path list at any time:

```sh
git fetch --no-tags upstream develop
git diff --name-only upstream/develop...HEAD
python3 scripts/ybx_upstream_sync.py --check-inventory
```

The last command fails when a changed path is missing from this inventory or when
an inventory row no longer matches any file.

## Area table (machine read by the sync script)

Risk is the chance that upstream edits the same lines. Handling says what to do
with a conflict:

- `reapply` — take the upstream side, then re-apply the small YBX rename.
- `merge` — real three-way judgement on YBX behaviour; review each hunk.
- `regenerate` — never hand-merge; re-run the generator after taking one side.
- `fork-only` — new fork-owned path; upstream conflict is unlikely.

## Details per area

### ota-channel

`OtaUpdater.cpp` is the most safety-critical fork file: a wrong merge can flash an
upstream image onto a YBX device.

- `latestReleaseUrl()` points at `api.github.com/repos/jhdvp/ybx-crosspoint/releases/latest`.
- Asset selection expects `ybx-<version>-<board>.bin`, board suffix `x3-x4`;
  `crosspoint-*` assets and other boards are ignored
  (`ReleaseJsonParserTest.cpp`: `YbxAssetsDoNotSelectUpstreamOrAnotherBoard`).
- A missing release tag is `NO_UPDATE`, not an error, so preview devices fall back
  to SD installation.
- `isUpdateNewer()` compares `%n`-validated numeric versions plus the `rc` suffix,
  matching how the release workflow names tags.

After any merge, re-check these four points by reading the function bodies — a
line-merge that keeps upstream's URL is a silent failure the build will not catch.

### release-workflows

Upstream adds board profiles to the release matrices constantly. The fork keeps
`x3-x4` only, so a merged conflict must resolve to the fork's one-entry matrix plus
the `ybx-` asset prefix, glob and count assertion (`1`, not `8`). `ci.yml` and
`pr-firmware-links.yml` only differ in naming text.

### catalog-auth

Fork behaviour, not branding: the YBX list index needs an account-scoped
authorization header and must handle an expired reader token.

- `loadBrowseListIndex()` returns `ListIndexResult{LOADED, UNAUTHORIZED, FAILED}`;
  `UNAUTHORIZED` offers device-code sign-in, a provider session error stays separate.
- `browseListsHeaders` is applied through `readHeaders`/`substitutedHeaders`.
- `PluginHttp` gained `timeoutMs` on `request`, `requestToFile` and
  `mintPasswordToken`, abort polling, and an explicit `file.close()` check.
- `FirmwareIdentity.h` advertises `catalog.lists.auth`; the plugin must not install
  without it.

Upstream is active in the same functions, so review the call sites rather than
trusting a clean merge.

### ybx-home

Home is gated on `FREEINK_DEVICE_X4 || FREEINK_DEVICE_X3`; other board profiles keep
the upstream home. `HomeActivity` gained `ybxHomeUi`, `ybxMore`, `ybxMoreChoice`,
`onMoreOpen()`, recent-cover loading in `onEnter`/`loop`/`render`, and
`activateSelection`. Layout and navigation math lives in `src/util/YbxHomeLayout.h`
so `test/ybx_home` can test it on the host. Back resumes the latest book; empty
devices start at Library; Catalogs appears only when Plugins is enabled or OPDS is
configured.

### sleep-events

`deliverSleepPluginEvents()` in `src/main.cpp` drains with a bounded budget
(`drain(&renderer, 4, 15000)`), uses a `millis()`-rollover-safe join loop, and logs
the skip reason. New fork-owned headers: `PluginEventQueue.h` (`drainQueue`),
`PluginQueueStorage.h` (`repairQueueTail`, `recoverQueue`, `replaceQueue`),
`PluginEventDeadline.h` (`EventDeadline`, shared across 401/403 retries).
`PluginEvents.{h,cpp}` adds the `latestSnapshot` path with `"delivery": "latest"`,
per-handler deadlines (8000 ms snapshot, 2000 ms ordinary, 30 s cap) and
512-byte torn-append truncation. Keep the queue storage contract
(`.pending`/`.bak`) and `docs/plugin-events.md` consistent: the documentation is
part of this area, not free cleanup.

### branding, docs, tests

Single-line renames that are cheap to re-apply but easy to lose silently: boot and
sleep wordmark, About row, Calibre/mDNS/web-server hostnames, HTTP user agents,
web panel titles and footer links, `USER_GUIDE.md` wording (`ybx.local`),
`scripts/git_branch.py` log text, and the user-guide generator.
`README.md` and `USER_GUIDE.md` are upstream's most-edited files: expect conflicts
and treat upstream's new user-facing features as content to port into the YBX
README, while the verbatim upstream copy lives in `README-UPSTREAM.md`.
`docs/ybx-validation-status.md` records what is and is not verified; update it in
the same change as any behaviour a reader can notice.

## Protected identifiers

These are protocol or credential identities, not branding, and must survive every
merge. The sync script's invariant check greps for them:

- Settings, progress and caches stay under `/.crosspoint/`.
- The browser plugin API stays `window.CrossPoint`; the compatibility family stays
  `crosspoint`.
- The OTA repository and asset prefix stay `jhdvp/ybx-crosspoint` / `ybx-`.
- The FreeInk SDK stays at the pinned gitlink (no silent SDK advance).
- `catalog.lists.auth` stays advertised while the YBX plugin requires it.
